# ADR-0022: Content-free CPU runtime measurements

Status: accepted for the scalar CPU reference service.

## Decision

The existing fixed 17-value service metrics schema is populated without wire
changes. Each scalar forward-token call is timed with Rust's monotonic
`Instant`. Prompt tokens contribute to prefill nanoseconds and forward calls
after the first sampled token contribute to decode nanoseconds. Single-stream
and bounded round-robin paths use the same accounting rules.

Successful terminal usage adds prompt and generated token counts. Throughput is
the cumulative generated-token count divided by cumulative measured forward
time, represented as tokens per second multiplied by 1,000. Checked `u128`
intermediate arithmetic prevents overflow; the public `u64` value saturates
only if the mathematical result exceeds its representation. A zero measured
duration reports zero rather than inventing performance.

Live host memory is the sum of loaded model-pool reservations. Live KV memory
is the sum of exact contiguous-cache reservations. CPU device memory is zero.
Prompts, generated bytes, model paths, tensor values, key material, and per-user
labels never enter metrics.

## Consequences

The metrics are suitable for local health, pressure, and trend observation but
are not benchmark evidence. They include decoder forward work rather than
tokenization, event encoding, socket backpressure, or caller latency. Hardware
backends require their own reviewed timing and device-allocation accounting.
